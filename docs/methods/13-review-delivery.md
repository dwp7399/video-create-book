# 13 评估、修改与交付：让问题回到正确的决定

质量不是技术缺陷越少越好这么简单。作品首先要在约定观看条件下完成表达，同时避免人物、事实、产品、动作和声音的意外错误。本章接[目标与方法论](../guide/01-methodology.md)、[制作协作](12-production.md)和[AI 工作流](../ai/A1-content-design.md)。以下案例及反馈均为示范表格，不是真实的观众实验或投放结果。

## R14-01 用分层检查区分表达问题与执行缺陷

**定义与机制。** 分层检查先确认作品希望观众理解和感受什么，再判断信息链、视听组织与技术实现。它使“看不懂”不被误治为“颜色不够电影感”，也避免创作者以“风格”掩饰事实或物态错误。

**适用与边界。** 适用于纸面分镜、动态分镜、粗剪和成片，但能验证的范围不同：文字方案可以检查因果与时间，无法证明表演真实、对白可懂或AI运动稳定。每份报告必须写当前检查对象与未检查范围。

**准备与步骤。**

1. 从简报抄出一个核心理解目标、一个体验目标及观看条件。目标不明确时回立项，不凭评审者喜好增加风格要求。
2. 按正常播放先看一次，只记阻碍理解或感受的位置；第二轮才分项细查，避免逐帧先找小毛病而忘记全片。
3. 用下表记录“通过/失败/待验证/不适用”。不适用需写理由，未测试不能等同通过。
4. 为问题标注“意图内偏离/意图外缺陷/待验证”。越轴、跳切、不现实运动可能是设计，但必要信息与规则仍需一致。
5. 给出问题所在时间、实际征象、影响、可能原因及建议验证；不把原因猜测直接写成结论。
6. 阻断性问题优先修复，再复验受影响范围。审片得分不能抵销虚假事实或缺失关键证据。

| 检查层 | 可观察问题 | 检查方法 | 失败后优先返回 |
|---|---|---|---|
| 目标与理解 | 能否复述主题、操作或主张；是否误认人物动机 | 首次自由复述，与简报比较 | 目标、研究、结构 |
| 情绪与节奏 | 哪段期待建立/释放；哪里注意离开 | 标时间的开放反馈；比较两版但不暗示答案 | 结构、表演、时间、声音 |
| 事实与证据 | 论断是否有素材支持；剪辑是否伪造因果 | 主张逐项对照原始素材与来源 | 研究、脚本、剪辑 |
| 人物与身份 | 脸、服装、体态、关系、视线是否意外改变 | 正常速度看关系，定格辅助核对身份 | 资产、选条、生成/动画 |
| 产品与物态 | 型号/结构/数量/接触/开合状态是否一致 | 对照实物或批准参考；检查前后状态 | 生产、合成、选片 |
| 动作与物理 | 起落、重心、受力、接触、轨迹是否符合既定规则 | 正常速度看重量，慢放定位穿透或漂移 | 调度、表演、动画、AI |
| 空间与时间 | 谁在哪里、朝哪走、是否同时发生能否辨认 | 画空间图和事件线，对照镜间方向 | 调度、镜头、剪辑 |
| 声音与同步 | 口型、落点、声源距离、环境连续、对白遮蔽 | 试听/合看，核查接触瞬间及声画偏移 | 录音、同步、剪辑、混音 |
| 图文与观看条件 | 能否读完、是否挡关键动作、裁切是否丢信息 | 按目标屏幕与观看条件实际播放 | 文字、版式、交付 |
| 文件与版本 | 正确版本、时长、音轨、字幕是否完整 | 对导出文件从头到尾回看 | 输出、媒体管理 |

不要用“动作符合物理”否定已建立规则的夸张动画；应检查规则是否稳定、动作是否可读。同样，纪实可信度不能靠画面“像纪录片”保证，必须追溯事实来源。

**案例 B 的基础与变化。** 基础评审只问“支架好不好看”；变化评审要求：能否看出设备由支架支撑、演示条件是否仍在画面或说明中、折叠前设备是否取下、支架结构是否保持同一、收纳前后数量是否一致、不宣称耐重/寿命。产品和视频目标不变，评价从审美印象转为表达与证据；审美仍可评价，但不能遮住虚假演示。

**组合、错误与返修。** 与下节返修单组合。只有“整体不高级”：要求指出具体信息/光色/动作问题；一个微小背景闪烁被排在错误产品结构前：按影响重排；静音看不懂便判所有作品不合格：回简报，只有目标要求无声理解才如此验收，MV可依赖音乐。

**检查及媒介适配。** 目标、情绪、连续性和可执行修改是否分别有证据？实拍重点包含实际表演和现场声音；动画增加姿态/曲线/受力；AI增加身份漂移、短暂变形、产品细节及意外声画。所有路径都必须检查事实与成片完整性。

## R14-02 先定位根因，再按影响范围返修

**定义与机制。** 返修定位把观众看到的症状连接到最早产生错误的决定，并估计改动会影响哪些下游素材。结构性问题只做表面修饰通常会重复返工；反之，可用剪辑解决的停顿不必重拍整场。

**步骤。**

1. 先描述症状，不立刻指定手段。例如“11秒后观众以为林已把伞卖出”，比“再生成一个更犹豫的表情”更可诊断。
2. 列可能原因并找证据：是否缺少停手、是否切到持伞状态、是否声音暗示交易已完成？先检验最直接影响意义的原因。
3. 按影响分级：阻断发布/表达的问题优先；明显损害理解或情绪的次之；局部质感问题后置。等级由本片目标决定，不按修复难度决定。
4. 为每条问题给最小修改与备选方案；写清需要重做的下游资产/声音/字幕，不假设局部修复无连带影响。
5. 修改后既复看该处，也检查前后连接及全片意义；更新版本记录，不把旧反馈直接当新版仍然存在。
6. 关闭问题需验收证据；若无法修复，记录残留影响及采用原因，明确是否仍满足发布条件。

**案例 A：返修单示例。** 以下是“若出现该问题”的预案，不是已发生缺陷。

| ID/级别 | 征象与影响 | 根因验证 | 最小修改/备选 | 验收 |
|---|---|---|---|---|
| A-R01 阻断 | A13-04林手中出现伞，观众误以为已取走 | 对照03末帧与04全镜 | 换没有持伞的候选；或重做04；不以裁切遮挡全部关系 | 伞仍在架，未出现完成交接的新事实 |
| A-R02 重要 | 观众不知道周与迟疑有关 | 检查02是否可辨；04望门方向是否成立 | 延长可辨认的02或调整视线覆盖；时长改变须重算全片 | 首次复述能建立可能关联，仍不强制唯一情绪 |
| A-R03 重要 | 手停住被看成播放卡顿 | 检查03是否完全静止、雨/衣料是否持续 | 保留微小自然动作或重做动作；不无依据加大音效 | 停顿读为人物选择而非技术冻结 |
| A-R04 局部 | 柜台边缘短暂闪烁，不影响动作 | 正常速度确认干扰程度 | 局部合成或换候选；若成本过高记录残留 | 注意不再被边缘吸走，修复未破坏手部 |

基础版对所有问题都“重新生成整镜”；变化版按症状定位再选择剪辑、声音、局部合成或重做。保留表达目标，改动返修路径；在实际执行前不声称效率已提升。

**组合。** 接预算设置停止条件；接资产台账定位影响范围；接观众测试确认理解修复。若结构改动导致对白、字幕、音乐同步全变，按版本整体更新，不只导出画面。

**错误→返修。** 多人意见互相矛盾：先区分不同受众/观看条件，不用多数表决掩盖目标冲突；同一问题修三次仍出现：回更上游的因果或布局；为了修小瑕疵破坏表演：比较收益与艺术代价，保留更有效的版本。

**检查及适配。** 改动是否解决观众症状？原有情绪节拍是否保留？邻镜状态和声音是否受损？工时是否可承担？实拍可能需要补镜/补声；动画可在资产、动作或合成层返修；AI须判断局部修改是否稳定，否则采用替代媒介。

## R14-03 用首次观看测试检验理解与体验

**定义与机制。** 试看让未读脚本的人按目标条件观看并自由反馈，揭露创作者因熟悉素材而自动补全的信息。它检验的是具体版本和观看情境，不是宣布某技法对所有观众有效。小规模反馈用于发现问题，不推断总体提升率。

**操作。**

1. 按目标受众邀请观看者，记录其相关经验与观看条件，避免只找参与制作的人。按片子敏感程度处理素材分享和反馈留存。
2. 首次播放前不解释剧情、主张或“这里应该紧张”；只给必要观看条件，例如手机、声音开启或目标要求的静音。
3. 播放后先问“你看到了什么、发生了什么变化”，再问“你在哪一刻开始期待某件事、哪里不确定”。避免先问“你是不是看出林在犹豫”。
4. 最后用有针对性的问题查关键关系、操作或证据；区分自由复述未提及和追问仍误解，二者不是同一严重程度。
5. 对照两版时，一人反复看会带入已知信息。尽可能让不同首次观看者分别看A/B；若只能同一人看，变换顺序并记录局限，不宣称严格因果实验。
6. 把反馈转为可修改假设，做一轮修订后重新找首次观看者。没有成片时只能做脚本/分镜阅读测试，并明确替代表演与声画效果尚未验证。

**可复制试看记录。**

| 字段 | 记录内容 |
|---|---|
| 版本与阶段 | 文件ID、日期；脚本/动态分镜/粗剪/成片 |
| 观看条件 | 屏幕、距离、声音、字幕、是否首次、是否熟悉题材 |
| 自由复述 | 尽量记录原话，单独写评审解释 |
| 注意/情绪 | 对方指出的时间与感受；不替对方填“紧张” |
| 理解检查 | 对应本片目标的问题、回答与不确定程度 |
| 待验证根因 | 缺信息/遮挡/声音/节奏等假设及证据 |
| 修改及复验 | 问题ID、新版本、下次要验证什么 |

**案例 C。** 修补台记录的首次观看问题可以是：“这件衣物先检查了什么？后来做了什么？哪些原因是当事人说的，哪些只是你推测？”不能预设尚未采得的采访内容。基础测试只问“感不感人”；变化测试分开事实复述与情绪反馈，防止音乐制造的感动掩盖过程误读。保持素材真实，不为符合反馈虚构新事实。

**组合、错误与检查。** 与证据台账核对观众推断；若所有问题都在暗示正确答案，改为开放提问；少数人不喜欢风格不等于表达失败，检查是否仍属于目标受众。结果能否说明理解、情绪和连续性各出现了什么，而非只收集喜欢/不喜欢？实拍、动画、AI均使用同样方法；呈现阶段不同要标注，不把动态分镜反馈当最终表演效果。

## R14-04 交付正确版本，并让复盘反馈创作

**定义与机制。** 交付同时包括内容、文件、观看支持与项目归档；发布复盘把实际观看行为与反馈对应到创作假设，而不是以单一播放量判定全部质量。适用于自用、客户交付和公开发布；平台具体参数应执行前查当前官方要求，并记录日期。

**步骤。**

1. 锁定批准版本与发布范围；检查素材来源、许可和人物同意等项目记录是否支持该用途，待确认项不要假写“已授权”。
2. 建交付规格表：画幅、尺寸、帧率/时间基、编码容器、音轨、字幕形式、封面/标题、目标观看条件和当期平台要求。技术值来自项目与渠道，不抄通用“万能设置”。
3. 根据目标受众检查可访问性：对白字幕之外，必要时描述身份、动作、场景变化等关键视觉信息；把说明安排在不遮蔽关键对白的位置。字幕不能自动替代全部视觉描述，具体形式按项目用途设计。
4. 导出后检查最终文件而非只检查时间线：头尾、总时长、音轨、口型/接触同步、字幕显示、裁切、黑帧/离线帧、图形、关键证据；至少正常速度完整回看一次。
5. 在目标设备或可用预览环境检验。平台转码、裁切和封面显示若与预期不同，修输出版本并记录，不盲改原始内容。
6. 归档批准文件、可编辑工程、依赖、来源、反馈和残留问题。发布安排、链接、版本和日期进入台账。
7. 复盘分开曝光/点击、持续观看、理解/记忆、行动等维度，并记录可用数据边界。留存下降可提示检查某时段，但不能单凭曲线证明原因是镜头长度；标题、受众匹配和观看环境也可能影响结果。

**交付工作表示例 B。**

| 项目 | 发布前填写/验收 |
|---|---|
| 批准内容 | 仅本次桌面及设备条件下支撑、折叠与收纳；无耐重/寿命结论 |
| 版本与规格 | 文件ID、批准者、目标用途、画幅/尺寸/帧率/音轨；待项目确定 |
| 文字/声音 | 主张限制条件可读；动作声清楚；字幕与旁白信息不矛盾 |
| 画面关键检查 | 设备取下后折叠；支架结构一致；没有隐藏支撑或制造错误证据 |
| 导出复看 | 正常速度完整回看结果、设备、日期；待执行 |
| 发布与复盘 | 发布后实际链接、观察窗口、可用指标、评论中的误解；未发布则留空 |

基础交付只发“最终.mp4”；变化交付绑定批准版本、规格、观看支持与复盘问题。成片事实不变，降低错版和误读的风险。若为多画幅改版，重新检查构图、支撑点及文字，而非简单裁中心。

**错误→返修。** 视频在编辑器正常但导出无声：检查导出音轨映射并重新全片回看；字幕挡产品支撑点：改布局或断句，不能删证据；为了提高点击夸大主张：回事实范围和标题兑现；看到指标下降就加快全部镜头：先定位具体段落与其他可能原因，再做有边界的版本比较。

**检查及媒介适配。** 交付文件完整表达原目标吗？发布包装是否改变情绪预期或夸大承诺？声画/图文/物态在最终编码中仍成立吗？归档是否让下一位协作者能接续？实拍保留原始来源与同意记录；动画保留资产/工程依赖；AI保留输入与候选血缘及适用的披露要求，后者按实际用途查证，不在此写成普遍法律结论。

## 本章实践交付

交付一份分层评估、一组有时间定位的返修单、一份如实标注阶段的试看记录及交付/复盘表。未拍摄、未生成、未试看或未发布的项目均记“待验证”，无需为了让表格完整编造结果。优秀的交接报告既说明已经通过什么，也准确标出下一个人需要验证什么。
